1. Introducción

Este documento describe el plan de pruebas para el proyecto “YogurASO – Tienda web de yogurt artesanal”. Se utilizará la Pirámide de Pruebas para garantizar una estrategia de pruebas equilibrada y eficiente. YogurASO cuenta con frontend en HTML/CSS/JavaScript, backend Node.js + Express y base de datos PostgreSQL, con autenticación JWT, catálogo, carrito local, panel administrador y checkout por WhatsApp.

2. Alcance

El alcance incluye pruebas unitarias, de integración, de aceptación y end-to-end para YogurASO, cubriendo autenticación (/api/auth), productos (/api/products), middlewares de seguridad, páginas del frontend y la comunicación frontend–backend mediante frontend/js/api.js.

3. Estrategia de Pruebas

La estrategia se basa en la Pirámide de Pruebas:

  • Pruebas Unitarias (Base de la pirámide)
  • Pruebas de Integración (Capa intermedia)
  • Pruebas de Aceptación/Funcionales (Capa superior)
  • Pruebas End-to-End (Pico de la pirámide)

4. Detalles de la Estrategia de Pruebas

4.1. Pruebas Unitarias

  • Objetivo: Verificar unidades de código (funciones/métodos).
  • Herramientas: Jest (JavaScript/Node.js).
  • Casos: Validaciones de authController.js, totales de cart.js, utilidades de utils.js.
  • Responsabilidad: Desarrolladores.
  • Cobertura: Al menos 80% del código crítico.

4.2. Pruebas de Integración

  • Objetivo: Validar interacción entre módulos/servicios.
  • Herramientas: Postman (API) y Mocha/supertest (opcional).
  • Casos: PostgreSQL ↔ backend; authRoutes/productRoutes; consumo desde api.js.
  • Áreas clave: BD, API REST y middlewares verifyToken.js / rateLimit.js.

4.3. Pruebas de Aceptación/Funcionales

  • Objetivo: Cumplir requisitos funcionales.
  • Herramientas: Postman (API) y Playwright (UI).
  • Casos: Formularios login/registro, CRUD admin, catálogo y carrito.

4.4. Pruebas End-to-End (E2E)

  • Objetivo: Flujo completo de extremo a extremo.
  • Herramientas: Playwright (UI/E2E) y Postman (API).
  • Casos: Interfaz → Backend Express → PostgreSQL.
  • Áreas clave: Registro, login, productos, carrito, admin y 404.

5. Criterios de Aceptación

  • Unitarias: Todas pasan; cobertura crítica ≥ 80%.
  • Integración: API y PostgreSQL validados.
  • Aceptación: Login, catálogo, carrito y admin aprobados.
  • E2E: Flujos críticos sin errores bloqueantes.

6. Ambiente de Pruebas

  • Desarrollo: Unitarias e integración. API en localhost:3000; frontend estático.
  • Staging/local integrado: Aceptación, Postman y Playwright.

7. Planificación de Pruebas

  • Desarrollo: Unitarias + integración (Postman).
  • Pre-lanzamiento: Aceptación y E2E (Playwright).
  • Post-lanzamiento: Regresión de auth, productos y vistas.

8. Recursos y Herramientas

  • Humanos: Aprendiz desarrollador e instructor/interesados.
  • Herramientas: Jest, Postman, Playwright, Node.js, PostgreSQL, Chromium.

9. Riesgos y Mitigación

  • Riesgo: Baja cobertura en auth/CRUD. Mitigación: Ampliar Postman y regresiones Playwright.
  • Riesgo: Falla frontend–backend (CORS/token). Mitigación: Probar /api/health y Authorization.
  • Riesgo: BD no disponible. Mitigación: Validar conexión al arrancar server.js.

10. Comunicación y Reportes

  • Frecuencia: Al cerrar cada batería Postman/Playwright.
  • Formato: Progreso, defectos, capturas y métricas PASS/FAIL.

Conclusiones

Este plan de pruebas pretende asegurar que “YogurASO – Tienda web de yogurt artesanal” cumpla con los requisitos de calidad esperados, usando la Pirámide de Pruebas. Postman cubre la API REST y Playwright la interfaz, alineados con los módulos reales del proyecto (auth, productos, carrito y administración).
